# Issue #46: Remove a part without breaking the test

**Recommendation:** Add **Edit parts** for 3–5 dependency-checked **original** questions in Your paper. Show paper, key and recalculated marks together. Leave past papers unchanged on the public site. A separately authorized internal image-mask tool is possible only if the school's actual license covers editing and distribution of these specific copies. Do not start with OCR or bulk archive conversion.

The [issue](https://github.com/RktRobinhood/Math-AA---Question-Bank/issues/46) asks to hide a part (e.g. a calculus step), carry that selection into a test, and ideally reletter what remains. Start with unticking independent parts; if a later part actually needs an omitted result, show the problem and offer choices rather than knowingly exporting a broken question by default.

| Approach | Can do | What blocks it |
|---|---|---|
| **Crop or mask images** | Cover a rectangle or stitch approved strips. Fast for an independently marked tail with separately confirmed paper and key masks. | Keeping the same image height leaves blank gaps. Stitching needs reliable shared-stem boundaries and both label/marks geometry; a removed strip can swallow a definition, diagram, continuation, or shared marks. No text reflow or accessible maths. No automatic clean relettering/references. Rights-cleared internal fallback only; preserve source labels in first pass. |
| **Structured text + maths + diagrams** | Clean reflow, accessible text/maths, stable cross-references, natural renumbering, semantic printable HTML. | OCR doesn't recover reliable mathematical signs, diagram semantics, shared givens, mark groups or dependencies. Transcription is still reproduction subject to rights; no archive-wide conversion. Present paper PDF/DOCX place rasters, so this is a new export renderer. Start with HTML/print PDF and teacher-owned original material; editable Word equations are separate work. |
| **Dependency-aware authored originals + reroll** | Vary numbers in a tested original question, freeze a version, hide independent parts, update labels/marks/key. An authored alternative can supply a missing given or remove a downstream task. | The native engine has no dependency DAG, safe variants or formal mark-point criteria; its many MCQ/self-mark forms aren't automatically assessment-ready. Reroll the whole linked situation together. Save both a generator/revision/seed and final snapshot so publishing or updates cannot alter an already reviewed paper. **Best public pilot.** |

## Two useful prototype states (fully original)

For g(x) = x² − 6x + 5, ask for zeros (2 marks), gradient at x = 2 (2), and solutions to g(x) = −3 (2). The last part uses the common stem but not a previous result. Hide the gradient and get a two-part **4-mark** paper and key: zeros 1, 5; solutions 2, 4.

In an extended version, add a fourth part that requires the earlier gradient to find the tangent at x = 2. If the gradient is omitted, offer to keep it, omit the dependent tangent, or select an authored alternative explicitly giving the slope −2. The tangent is y = −2x + 1. Giving the slope changes the task and can change marks; author/review an alternate key, not an automatic “same marks” rewrite.

Keep shared givens/assets, required earlier result/method, optional scaffolds/approved alternatives, and marking rules separate. The [IB AA 2021 specimen pack](https://www.ibo.org/globalassets/new-structure/university-admission/pdfs/dp-mathematics-analysis-and-approaches-specimen-papers-en.pdf) provides reference-only examples: SL P1 Q8 asks students to use a derivative graph in a later explanation and groups subpart marks; HL P2 Q12(d) explicitly needs two earlier results. Its examiner guidance distinguishes later follow-through, shown working, inadmissible values, and what happens if a mistake makes the task much easier. **Follow-through after an error isn't the same as deleting the task.** Keep examiner-style marks teacher-reviewed.

## Staged delivery

1. **Prototype:** original examples only. Light “Edit parts” control, stable part IDs underneath display letters, live marks, reversible edit. Explicit “Keep prerequisite”, “Remove both”, or signed-off authored replacement. Warn/block unresolved dependencies and partial selections of bundled mark groups. No public link containing IB source.
2. **Pilot:** 3–5 teacher-reviewed original forms covering independent deletion, a hard dependency, shared diagram/table, and an alternate with a revised rubric. Resolve one entry consisting of entry ID, source ID, revision, seed and selected part IDs into both preview and export; consume the same model for paper and separate key. Recompute marks/topic/duration, preserve course and calculator policy deliberately, and keep answer/key bytes out of student exports. Reroll before freeze and recheck domain, graph, answers and marking. Test numbering/nested references, no solution leakage, font/page breaks, replay of saved revisions and teacher review reset. Leave the public archive intact.
3. **Later:** structured teacher authoring, optional verified DOCX, then formal rubric features if useful. [1EdTech QTI 3.0](https://www.imsglobal.org/sites/default/files/spec/qti/v3/info/index.html) is an interchange reference separating item body, response processing and scoring, not a turnkey dependency editor. [STACK multipart authoring](https://docs.stack-assessment.org/en/AbInitio/Authoring_quick_start_7/) and [seeded variant deployment](https://docs.stack-assessment.org/en/STACK_question_admin/Deploying/) are practical precedents for explicit student-answer dependencies, tested variants and stored seeds; neither is needed as a runtime dependency.
