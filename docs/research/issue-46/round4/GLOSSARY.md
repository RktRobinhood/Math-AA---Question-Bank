# Proposed Question Studio glossary

| Term | Meaning |
|---|---|
| **Block** | Named authoring unit: context, model, marked question part or written prompt. Has a stable ID. “Block 2” means position in the workspace, never an IB paper number. |
| **Part** | A visible, labelled assessed item such as (a). Letters are assigned from visible order, not used as IDs. |
| **Port** | Named, typed input or output on a reusable block. A wire does not mean two blocks share all maths. |
| **Derived-value link** | Connects authored data or calculated canonical values. |
| **Printed reference** | Injects the current visible part label; missing dependencies block the preview, not the draft. |
| **Follow-through rule** | Explicit conditional marking rule using a validated earlier learner answer. Never rewrites the canonical key. |
| **Assessment profile** | Course + syllabus version + exam paper/section style. It defines technology and response-length expectations separately. |
| **Template family / variant** | A reviewed reusable reasoning pattern / its frozen data instance from a bounded generator and seed. A changed value is not a distinct family. |
| **Primary skill / secondary tags** | One owner of a part’s mark weight; secondary tags allow discovery or evidence counts without counting those marks again. |
| **Test blueprint** | A selection and intended weight for topics, skills and demands. Teacher targets are not IB mandates. |
| **Archive reference** | An exact source identity and permission/provenance record for an existing exam. Not a right to republish or a generative template. |
| **Ready to review** | Technical checks pass; teacher validation of demand, wording and marking still required. |
